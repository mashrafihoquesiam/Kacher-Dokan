# Kacher Dokan v16 — FINAL Project Show Build

This build is based on v15 and keeps the working Customer + Seller + Rider workflows while adding cloud portability and final reliability fixes.

## What v16 adds

- **Render-ready web/backend deployment** via `render.yaml` and `/healthz`.
- **Cloudinary image storage** for new profile/product uploads when `CLOUDINARY_URL` is configured.
- **Local development fallback** for uploads when running on a laptop without Cloudinary.
- **Existing-image migration tool** so old `/uploads/...` photos can be moved to Cloudinary and their MongoDB URLs updated.
- **Portable mobile registration photos**: Expo now sends image data to the backend instead of saving a phone-local `file://` path in MongoDB.
- **Cloud mobile configuration** using `EXPO_PUBLIC_API_URL=https://YOUR-RENDER-SERVICE.onrender.com`.
- **EAS build configuration** (`kaser-dokan-mobile/eas.json`) for installable Android/iOS builds after Expo project setup.
- **Authentication hardening**: the old universal `123456` bypass is removed. Existing legacy passwords still work, and a successful legacy login is automatically upgraded to a salted `scrypt` password hash.
- **Seller cancellation notification bug fixed**.
- **Browser voice fallback**: if Edge TTS is unavailable, the seller announcement tries the browser speech engine.
- **Mobile customer shop/product refresh tightened to ~4 seconds** for faster cross-device photo/product synchronization.
- Removed misleading `Connected to localhost:27017` text from the DB inspector.

## 1. Local development

### Web/backend

```bash
cd kaser-dokan-web
cp .env.example .env
# Put your real MongoDB Atlas URI in .env
npm install
npm start
```

Open `http://localhost:3000`.

### Expo mobile on the same Wi‑Fi

Keep `kaser-dokan-mobile/.env` as:

```env
EXPO_PUBLIC_API_URL=http://YOUR_LAPTOP_IP:3000
```

Then:

```bash
cd kaser-dokan-mobile
npm install
npx expo start --lan
```

## 2. Cloud image storage (required for portable uploaded photos)

Create a Cloudinary account and copy the server-side environment variable from the Cloudinary console:

```env
CLOUDINARY_URL=cloudinary://API_KEY:API_SECRET@CLOUD_NAME
```

Put it only in the **backend/server environment**. Do not put the API secret in Expo/mobile code.

When this value exists, new profile/product uploads are stored in Cloudinary and MongoDB stores the returned HTTPS URL.

### Migrate old local photos from your current laptop

Your old uploaded JPG/PNG files were not inside the v15 ZIP, so they cannot be moved automatically from this ZIP alone.

On the laptop that still contains the original `kaser-dokan-web/uploads/` files:

1. Put `MONGO_URI`, `DB_NAME`, and `CLOUDINARY_URL` in `kaser-dokan-web/.env`.
2. Make sure the original local `uploads/` folder is inside this final project's `kaser-dokan-web/`, **or** set `LEGACY_UPLOAD_ROOT` to the old `kaser-dokan-web` folder.
3. Run:

```bash
cd kaser-dokan-web
npm run migrate:images
```

The script uploads local profile/product images, replaces MongoDB image URLs with Cloudinary HTTPS URLs, and keeps the original files untouched for safety.

## 3. Deploy web + backend to Render

The root contains `render.yaml`.

Recommended flow:

1. Put this project in a Git repository.
2. In Render, create a Blueprint/Web Service from that repository.
3. Set these secret environment variables when Render asks:
   - `MONGO_URI`
   - `CLOUDINARY_URL`
4. `AUTH_SECRET` is generated by the Blueprint.
5. Deploy.

Your public URL will look similar to:

```text
https://kacher-dokan.onrender.com
```

The same URL serves the website and API. Socket.IO also uses that server.

## 4. Connect Expo/mobile to the cloud server

After Render gives you the final HTTPS URL, use it as:

```env
EXPO_PUBLIC_API_URL=https://YOUR-RENDER-SERVICE.onrender.com
```

For Expo Go, update `.env` and restart Expo with cache clear:

```bash
npx expo start --clear
```

For a standalone project-show build, configure your Expo/EAS project, set the same `EXPO_PUBLIC_API_URL`, then build using the included `eas.json`.

## 5. Important project-show notes

- MongoDB Atlas holds users, shops, products, orders, stock, payments, cancellation history, rider data, notifications, etc.
- Cloudinary holds uploaded profile/product image files. MongoDB stores their permanent HTTPS URLs.
- bKash/Nagad/Upay in this project are **demo/simulated payment flows**, not a live merchant gateway.
- Web profile/shop/product updates use Socket.IO. Expo customer shop/product data refreshes automatically about every 4 seconds.
- Edge TTS is online; the web UI now has a browser speech fallback if the TTS request fails.
- The active cloud deployment in this build targets the current working **Node/Express backend**. The separate Spring Boot folder remains in the project but is not the feature-complete runtime used by the web/mobile clients.

## 6. Recommended 5-minute demo flow

1. Customer logs in and sees available shops on the map.
2. Customer opens a shop, adds products, and confirms the cart.
3. Customer completes a demo bKash/Nagad/Upay payment.
4. Seller receives the Bangla payment announcement and sees transaction ID/history.
5. Seller changes order to preparing; customer cancellation becomes unavailable.
6. Rider accepts the delivery; seller accepts rider; pickup code is verified.
7. Show rider tracking/order delivery.
8. Change seller profile/product photo on one device and show the customer-facing update on another device.
9. Show seller inventory edit/unavailable/delete + low-stock reminder + analytics.

Do not add new major features immediately before the show. Use the remaining time for repeated end-to-end testing.
